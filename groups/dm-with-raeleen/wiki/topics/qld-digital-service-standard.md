# Queensland Government Digital Service Standard

_Topic: Government compliance standard_
_Source: https://www.forgov.qld.gov.au/information-technology/queensland-government-enterprise-architecture-qgea/qgea-directions-and-guidance/qgea-policies-standards-and-guidelines/digital-service-standard_
_Last updated in wiki: 2026-06-08_

## Overview

Mandatory QGEA standard effective January 2022. Applies to all new or significantly redeveloped high-volume transactional digital services. Based on the Australian Government Digital Service Standard, adapted for Queensland. Services must be assessed before moving from Beta to Live, with remediation of any outstanding issues.

## The 13 Criteria

1. Understand user needs
2. Have a sustainable multi-disciplinary team
3. Use agile and customer-centred processes
4. Understand the tools and systems required
5. Make digital services secure
6. Build consistent and responsive design
7. Use open standards and/or common platforms
8. Make source code open by default
9. Make digital services accessible
10. Test the digital service
11. Measure the performance and improve
12. Don't forget the non-digital experience
13. Encourage a shift to the digital channel

## Relevance to DTET High Performance Website

| Criterion | How DTET project addresses it |
|---|---|
| 1. Understand user needs | Strategy workshops, user journey analysis, blueprint |
| 5. Make digital services secure | SSO via AD, access logging, private portal |
| 6. Build consistent and responsive design | Responsive design across all breakpoints, design system |
| 7. Use open standards / common platforms | WordPress (open source CMS) |
| 8. Make source code open by default | WordPress core is open; custom code — may have exemptions for internal tools |
| 9. Make digital services accessible | WCAG AA throughout design and build |
| 10. Test the digital service | QA across browsers/devices, UAT, post-golive QA |
| 11. Measure performance and improve | Access logging, content feedback (relevance rating), revision history |

## Notes

- Criterion 8 (open source) may have carve-outs for internal staff portals — worth flagging with DTET
- Criteria 12 and 13 are less relevant for an internal staff portal (it IS the digital channel, and there is no non-digital equivalent)
- This standard should be referenced in the DTET proposal and blueprint document
